# 实验性浏览器 SSH 隧道

同一套 LanTerm 同时提供两个能力，不区分单独的 server/client 安装包：

- 将本机 `127.0.0.1:<sshd 目标端口>` 映射到现有 Web 端口的 WebSocket 接口。
- 在本机 `127.0.0.1:<SSH 转发端口>` 接收普通 SSH 客户端连接。

浏览器打开远端页面后，连接远端同源 WebSocket 和本机回环 WebSocket，在两端之间转发数据。平台登录态由浏览器持有，不需要复制平台 Cookie。LanTerm 不启动或配置 sshd；远端需已有可用的 sshd 和 SSH 登录凭证。

## 启用和手动配对

本机和容器使用相同入口，分别在各自机器启动：

```bash
./launch.sh --experimental-ssh --ssh-target-port 22 --ssh-listen-port 2222
```

已有启动参数（如 `--port`、`--state-dir`、`--cwd`、`--public-url`）照常保留。目标 sshd 不是 22 端口时修改 `--ssh-target-port`。本机和容器可以使用不同端口。目标端口与转发端口不能相同；多个实例在同一台机器运行时，Web、SSH 监听端口必须分别错开。

1. 在本机浏览器打开 `http://127.0.0.1:8766/ssh`，登录本机 LanTerm。
2. 在第一块表单填写远端 LanTerm 完整地址，例如 `https://平台/.../proxy/8766/`，生成并复制配对信息。此信息含临时凭证，不要分享、记录到日志或提交到 Git。
3. 在**同一台本机的浏览器**打开远端 LanTerm，点击侧边栏的「SSH 实验」，或访问其路径下的 `ssh` 页面。完成平台和 LanTerm 登录。
4. 在远端页面的第二块表单粘贴配对信息，点击「连接隧道」。本机桥接会核对配对密钥和远端页面的 Origin。
5. 页面显示已连接后，在本机终端执行：

```bash
ssh -p 2222 容器用户名@127.0.0.1
```

SSH 仍校验容器的主机密钥，并使用容器用户名、密码或 SSH 私钥认证。本机端口被配对到另一个容器时，注意核对目标主机密钥；可为不同容器配置独立 `HostKeyAlias`。

```sshconfig
Host qz-lanterm
    HostName 127.0.0.1
    Port 2222
    User 容器用户名
    HostKeyAlias qz-lanterm
    ServerAliveInterval 30
    ServerAliveCountMax 10
```

然后使用 `ssh qz-lanterm`、`sftp qz-lanterm`，或让其他 SSH 工具连接这个主机配置。上述保活容忍时间应大于计划中的 WS 断线间隔；sshd 自身的超时也可能先结束连接。

## 断线行为

两个后端持有 TCP 连接，浏览器只持有可替换的 WebSocket。数据按序号记录，接收端确认后才释放；重连后补发未确认的数据，并跳过已接收序号，避免重复写入。TCP 的 EOF 也参与有序传输，支持半关闭。单条隧道最多同时持有 16 个 TCP 流，每个方向的数据发送窗口为 32 × 16 KiB；另有有界控制帧及操作系统、WebSocket 和每流读缓冲。窗口满时暂停读取。

- 页面有「模拟 WS 断线并重连」按钮，关闭两条 WS，3 秒后接回同一隧道。可在运行 SSH 命令时点击验证。
- 意外断线按 1、2、4、8、10 秒退避重连。2 秒一次的确认消息兼作心跳；浏览器检测到 12 秒没有消息会替换连接。
- 默认连续 120 秒没有收到有效隧道消息就清理 TCP 和缓冲，可用 `--ssh-resume-seconds 180` 调整，范围 15–600 秒。
- 此版本仍使用长 WS，依靠断线续传应对平台关闭连接；没有自动定时轮换或短 HTTP 请求模式。
- 刷新或关闭页面不会立即终止 TCP，但页面内存中的配对信息会丢失。保留原配对信息时，可在过期前重新粘贴连接。浏览器后台冻结或系统休眠可能使连接超过保留时间。
- 停止隧道、生成新本机配对、注销关联登录、服务退出、容器重启或超时会结束 SSH。服务重启不支持恢复，也没有把 SSH 字节或凭证写入磁盘。
- 关闭 SSH 隧道不操作 tmux。需要远端命令在 SSH 结束后继续运行时，使用 tmux 等会话管理。

## 当前验证范围和限制

本机测试覆盖真实 sshd + OpenSSH 的同一远端进程跨 WS 断线继续工作、确认丢失后的去重、多个流在缓冲压力下续传、半关闭、配对鉴权与过期回收，以及 Chromium 中双实例手动配对和带平台代理路径的传输。

qz 平台的真实强制断线策略尚未验证。HTTPS 远端页面连接本机 `ws://127.0.0.1` 是否可用，取决于浏览器的混合内容和本地网络策略，以及平台额外设置的 CSP。实验页面仅额外允许连接回环 WS；普通终端页的 CSP 不变。如果浏览器询问本地网络访问权限，需要允许；如果策略直接阻止该连接，当前版本会提示失败，尚未集成本机 TLS 或扩展替代方案。相关背景见 [Chrome 本地网络访问说明](https://developer.chrome.com/blog/local-network-access)。

当前传输采用 JSON/Base64，所有 TCP 流共享有序消息队列；一个流的 TCP 写入阻塞可能暂时拖慢其他流。适合先验证 SSH 交互和小规模文件传输，不承诺高吞吐或任意时长的无缝恢复。

## 验证

测试需要本机安装 `ssh`、`sshd`、`ssh-keygen`；真实 SSH 测试生成临时主机密钥、客户端密钥和独立 sshd 配置，使用当前系统用户，不操作系统 sshd。

```bash
uv run pytest -q tests/test_ssh.py
npm run build
npm run test:e2e -- tests/browser/ssh.spec.js
```
